# CAPSULA 0.6.0-alpha.1 — evidence and remaining live gates

The repository contains the complete standalone Work OS plus integrated RAH, persistent agent computer transport, continuity and clean improvement capsules. This remains a private single-operator alpha, not a production-certified multi-tenant service.

| Area | Current evidence | Boundary |
|---|---|---|
| Work OS APIs and cryptography | Root unit/integration suite and signed literal-code worker smoke | Local source/process verification |
| RAH mission grants | Signed contracts, replay, scope/pool/dependency validation tested | Actual external Dot KVM fleet needs configuration and live acceptance |
| Persistent computers | Dedicated unique binding, retry-safe provisioning, exact project import, subscription-task transport | CLI sign-in stays in each guest; no successful subscription inference claimed |
| Agent evolution | Encrypted continuity, observations, procedure drafts, experiment proposals, exact active-skill references | No underlying model-weight changes or permanent assistant attachment |
| Improvement capsules | Frozen cases and revisions, separate worker dispatch, budgets, preserved failures, promotion/rollback | Acceptance cases measure their frozen objective; not general capability proof |
| Dot host runtime | Separate source suite covering recovery, imports, handoffs and recursive scheduling | Historical kernel/QEMU/browser receipts kept separate from current source |
| Container containment | PASS: actual per-job Docker execution in a separate ext4-root Linux VM; see receipts/clean-worker.json | Actual VM/container evidence is distinct from fixtures and Vultr deployment |
| Enterprise lane | Organization/workspace grouping | No tenant identity/RBAC isolation claim |
| Vultr challenge deployment | Deployment and inference adapters documented | Real Vultr URL, Serverless Inference and official demo still required |
| Wallet, external federation and attestation | Existing draft/contract surfaces retained | No real settlement, external Loom/Pocket federation, TEE or witness claimed |

Run the current checks in docs/ACCEPTANCE.md and inspect test-receipt.json and receipts/. Source tests alone cannot promote an unconfigured provider, worker or host to LIVE. The RAH scheduler is implemented and executable on its configured host; it is no longer accurately described as only a plan-generation interface.

**Explicit external gaps:** no live production worker/VM containment attestation; no integrated multi-user identity; no live external scheduler/RAH fleet acceptance; no proven actual Loom Cluster scheduling, Pocket Agent federation, LiveVault external key management, PARRALAX settlement; no real wallet signing or bank payment; no live model or cloud runtime deployment proof; no independent security audit.

**Go/no-go:** Never call this v1.0 until sandbox network controls, key isolation, multi-tenant access, attestation/external witness, load tests, recovery, and external API/vendor behavior have been verified. A public hackathon deployment may be labelled *alpha with real contained execution* only after validating the actual worker host's policy and capture evidence.


### v0.5 preproduction boundaries

- Root mission contract plus bounded delegation may run autonomous cycles via a
  separately opted-in scheduler. It does **not** grant production self-modification.
- Multi-tenant RBAC, external witness, managed secrets/KMS and remote SSO are not
  implemented. Payment proposals cannot sign or broadcast transactions.
- For the Vultr challenge, per-job worker isolation, live inference, public demo
  and recorded containment moment require evidence from actual infrastructure.
- Use `RELEASE_SCOPE.md` as the operator declaration of verified vs proposed lanes.
